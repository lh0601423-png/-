# 毕业设计需求书 v0.2

> 状态：需求收敛中。本文用于记录当前已确认的设计目标、系统边界与待决策项；未确认内容明确标记为“待定”，不作为既定项目事实。

## 1. 项目定位

当前工作名称为 **“AI 辅助模块化山体滑坡先遣救援机械”**。

本项目面向山体滑坡灾害救援场景，设计一套以无人履带式母机为核心、结合无人机与固定监测节点的 AI 辅助中大型模块化先遣救援系统。

目标用户为民用通用应急救援单位。系统主要承担进入高风险滑坡核心区域后的先遣侦察、环境感知、风险评估、灾害信息建立与救援辅助，不以人员搬运、伤员转运或重型工程清障为核心任务。

## 2. 最终交付

毕业设计最终以一套完整概念设计为主要交付，包含：

- 产品外观设计；
- CMF 设计；
- 机械结构概念设计；
- 系统架构设计；
- 任务与使用流程设计；
- 三维作品建模与效果表达；
- 展板与论文；
- 配套操作员控制界面（HUD）概念 UI 与可运行交互演示程序。

HUD 仅用于毕业设计概念演示，不连接真实救援机器人，不承担真实机械控制。目标运行设备为 Windows 笔记本 / 桌面电脑上的操作员工作站。HUD 需要形成可运行的交互演示程序，但交互、任务状态、风险变化与 AI 行为均允许使用预设场景和本地模拟数据驱动，不要求实现真实机器人通信或真实 AI / 路径规划算法。具体编程语言与前端框架将在后续技术路线讨论中决定。

## 3. 设计深度

机械部分设计深度限定为“概念结构”。

需要体现系统布局、模块关系、主要机构原理、任务流程和合理的空间 / 尺度逻辑，但当前不要求进入完整工程制造级设计，不以详细强度校核、完整电机与减速器选型、液压系统工程设计或可量产结构验证作为毕业设计主目标。

## 4. 系统组成

当前系统由三类核心单元构成：

1. **无人履带式母机**
   - 中大型无人地面平台；
   - 车体规模预计略大于普通乘用车；
   - 采用履带式移动底盘；
   - 作为主要载荷、感知、计算、通信与任务执行平台；
   - 提供模块化任务接口；
   - 具备一定的物资携带与拖拽能力。

2. **无人机**
   - 对地面平台难以快速覆盖的区域进行空中补充侦察；
   - 为灾害地形、风险区域与路径判断提供俯视信息；
   - 与母机共享任务和感知信息。

3. **固定监测节点**
   - 由母机布设到关键位置；
   - 主要承担地质风险持续监测；
   - 用于持续获取局部地表变化信息，为二次滑坡风险判断提供输入；
   - 重点方向包括地表位移、倾斜、振动等与地质稳定性相关的监测信息；
   - 具体传感器组合、部署方式和节点形态仍待定。

## 5. 核心应用环境

重点针对以下灾害现场条件进行设计：

- 坡地；
- 碎石与松散地形；
- GPS 失效或卫星定位不可靠区域；
- 粉尘；
- 烟雾；
- 局部断电与基础设施失效环境。

当前最重要的三类环境适应问题为：

1. 坡地通行；
2. 碎石 / 松散地形通行；
3. GPS 失效条件下的定位、导航与任务执行。

## 6. 核心任务流程

当前设定的典型任务链为：

**母机进入灾区并先遣侦察 → 无人机补充空中信息 → 布设固定监测节点 → 多源信息融合 → 建立灾害地图 / 风险地图 → 持续监测二次滑坡风险 → 形成动态危险与救援优先度地图 → 判断并标识相对安全区域 → 将结果提交给后续人工救援队。**

## 7. “相对安全区域”的定义

本项目中的“安全区域”不表示绝对无风险区域，而是依据当前感知和持续监测结果划定的、可供后续救援人员优先进入或阶段性作业的相对安全区域。

系统需要完成两类输出：

### 7.1 数字信息输出

通过操作员 HUD 中的二维战术地图形成一份持续更新的综合态势信息，至少包括：

- 动态危险分布；
- 风险变化趋势；
- 救援优先度；
- 相对安全区域；
- 已知可通行 / 不建议通行区域；
- 母机、无人机及监测节点状态。

### 7.2 现场物理标识

系统应能够对判定出的相对安全区域进行现场物理标识，使随后进入的救援人员能够在基础通信或视觉条件有限的情况下识别该区域。

物理标识的具体形式、布设机构和视觉语言尚待进一步设计。

## 8. AI 与人机协同原则

系统目标为高度自主，但不是完全脱离人工授权的全自主救援系统。

当前人机协同逻辑为：

1. 人类下达高层任务目标；
2. 系统基于现场感知进行环境理解、风险评估、导航 / 路径规划与任务规划；
3. AI 生成执行计划；
4. 人类确认计划；
5. 确认后由系统自主执行；
6. 执行过程中持续反馈环境、任务进度、风险变化和系统状态；
7. 出现超出授权或关键风险边界的情况时重新请求人工决策。

## 9. 当前明确不做的内容

- 不设置驾驶舱，以无人平台为基本形态；
- 不设置机械臂作为当前方案核心功能；
- 不进行人员搬运或伤员转运；
- 不以挖掘、搬移巨石、大规模清障等重型工程作业为核心任务；
- 不将机械结构推进到完整量产工程设计深度；
- HUD 不连接真实机器人，不承担真实机械控制；
- HUD 面向 Windows 笔记本 / 桌面电脑上的操作员工作站，不以移动端或真实车载控制器为主要目标平台；
- HUD 不采用三维地形作为主要交互地图，主视图限定为二维战术地图；
- HUD 演示允许完全使用本地模拟数据、预设灾害场景和脚本化任务流程；不要求接入真实传感器、无人机、母机、ROS、实时消息系统或远程控制链路；
- HUD 中呈现的 AI 规划、风险变化和任务执行属于概念交互演示，不要求实现真实 AI 推理、导航或路径规划算法；
- 当前不预设具体 HUD 编程技术栈；
- 当前不预设固定监测节点的具体传感器组合。

## 10. 当前设计工具

已经确定或计划使用的设计工具：

- Rhino；
- Blender；
- KeyShot；
- Figma。

HUD 面向 Windows 笔记本 / 桌面电脑浏览器运行，基准展示规格为 1920 × 1080、16:9 横屏，界面语言为英文。HUD 主地图已经确定采用二维战术地图，不以实时三维地形界面作为主要展示方式。

### 10.1 仓库内容边界

Git 仓库主要管理：

- 项目需求与研究 / 设计文档；
- HUD 源代码及其必要的小型界面资源；
- 与项目管理、验证和交付相关的文本配置。

Rhino、Blender、KeyShot 等大型建模源文件、渲染工程、缓存和大型素材不纳入当前 Git 仓库。需要在仓库中引用此类成果时，优先保存轻量导出图、说明文档或外部资产位置说明，而不是直接提交大型源文件。

## 11. 当前待决策项

后续需要继续讨论并形成明确结论的内容包括：

1. 固定监测节点在地质风险监测方向上的具体传感器组合；
2. 固定监测节点的最低必要功能、部署方式和节点形态；
3. 物理安全区标识采用何种形式；
4. HUD 的具体信息架构、页面层级和核心交互流程；
5. HUD 技术栈与计算机语言；
6. HUD 演示所需的模拟灾害场景、数据格式和脚本化任务状态机；
7. 母机的目标尺寸、载荷、坡度能力等关键概念参数；
8. 后续需求版本的变更与冻结规则。

## 12. 当前阶段

当前处于毕业设计前期需求定义与总体方案设计阶段。

在需求未进一步冻结前，应优先完成场景、任务、系统角色、功能边界和交互逻辑的收敛，避免过早进入细节工程实现或由工具 / 技术栈反向主导设计。
